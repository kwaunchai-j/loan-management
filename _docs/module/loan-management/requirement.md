# requirement — loan-management (ระบบขอยืมเงิน)

> เก็บความต้องการโดย `business-analyst` จากการสัมภาษณ์ผู้ใช้ (PM3) เมื่อ 2026-10-27
> สิ่งที่ผู้ใช้ยืนยันแล้วเขียนเป็นข้อเท็จจริง; สิ่งที่ยังไม่ยืนยันมีป้าย `(สมมติฐาน — ยังไม่ยืนยัน)` และอยู่ใน `## Open Questions`
> เอกสารนี้ไม่เลือก stack และไม่ออกแบบ schema — เป็นหน้าที่ของ `system-analyst`

## Overview

เว็บไซต์สำหรับจัดการการขอยืมเงินแบบครบวงจรของผู้ให้กู้รายเดียว (single organization): ผู้ยืมล็อกอินยื่นคำขอเอง, ผู้อนุมัติพิจารณา, ระบบคำนวณดอกเบี้ยตาม master data, ติดตามการชำระ, คิดค่าปรับเมื่อชำระช้า, เก็บประวัติของผู้ยืมแต่ละคน และออกรายงานกำไรขาดทุนกับรายงานผู้ชำระช้า

**ปัญหาที่แก้:** ปัจจุบันจัดการเงินยืมด้วยปฏิทินใน iPhone (แต่ละรายการมีเฉพาะ ชื่อผู้ยืม, จำนวนเงิน, วันครบกำหนดชำระ) ทำให้คำนวณดอกเบี้ย/ค่าปรับด้วยมือ ไม่มีประวัติรายคน และไม่มีรายงานกำไรขาดทุน

**ผลลัพธ์ที่ต้องการ**
- คำนวณดอกเบี้ยและค่าปรับอัตโนมัติ ไม่ต้องคิดเอง
- admin ได้รับแจ้งเตือนเข้าโทรศัพท์เมื่อมีคำขอใหม่ ใกล้ครบกำหนด และเลยกำหนด
- ดูประวัติการยืมและความตรงต่อเวลาของผู้ยืมแต่ละคนได้
- มีรายงานกำไรขาดทุน ผู้ชำระช้าสุด ยอดคงค้าง และสรุปรายผู้ยืม
- นำข้อมูลเดิมจากปฏิทินเข้าระบบได้ผ่านไฟล์ Excel/CSV

## Target Users & Roles

| บทบาท | ยืนยันแล้วว่าทำอะไร |
|---|---|
| ผู้ยืม | ล็อกอินด้วย username ที่ admin ตั้งให้ (ลืมรหัสผ่านให้ admin รีเซ็ตให้ — ยืนยันแล้ว); ยื่นคำขอยืมเงินเอง; เห็นเฉพาะข้อมูลของตัวเอง ได้แก่ สถานะคำขอ, ยอดที่ต้องชำระ/วันครบกำหนด/ค่าปรับสะสม, ประวัติการยืมและการชำระ |
| เจ้าหน้าที่สินเชื่อ | **ไม่ต้องมีบัญชีแยกใน MVP** — ผู้ใช้จริงคือ admin คนเดียว (ยืนยันแล้ว: "ทุก role คือ admin นั่นแหละ"); หน้าที่ตรวจคำขอและบันทึกรับชำระ admin ทำเอง; หากมีบทบาทนี้ในอนาคต **ไม่เห็นเลขบัญชีผู้ยืมและไม่บันทึกการจ่ายเงินให้ผู้ยืม** (ยืนยันแล้ว) |
| ผู้อนุมัติ | **เป็นคนเดียวกับ admin ไม่ต้องมีบัญชีแยกใน MVP** (ยืนยันแล้ว); อนุมัติ/ปฏิเสธคำขอ; **ดูรายงานได้ครบทั้ง 4 รายงาน** (กำไรขาดทุน, ผู้ชำระช้าสุด, ยอดคงค้างรวมและจำนวนสัญญาที่เปิด, สรุปรายผู้ยืม — ยืนยันแล้ว); **บันทึกการจ่ายเงินให้ผู้ยืมและเห็นเลขบัญชีผู้ยืมได้** (ยืนยันแล้ว) |
| ผู้ดูแลระบบ (admin) | ทำได้ทุกอย่าง รวมบันทึกการจ่ายเงินและเห็นเลขบัญชีผู้ยืม (ยืนยันโดยผู้ใช้); สร้างบัญชีผู้ยืมให้; ตั้งค่า master data; ยื่นคำขอแทนผู้ยืมและอนุมัติคำขอนั้นเองได้ (ไม่มีกฎแยกหน้าที่); **เป็นผู้รับแจ้งเตือนเพียงคนเดียว** (มี admin คนเดียว ยืนยันแล้ว) |

- บัญชีผู้ยืมสร้างโดย admin เท่านั้น (ผู้ยืมไม่สมัครเอง)
- ผู้ยืมไม่ได้รับการแจ้งเตือนใดๆ จากระบบ (ยืนยันแล้ว)
- ภาษาของระบบ: ไทยทั้งหมด (ยืนยันแล้ว)

## Core Features

**F1 — บัญชีผู้ใช้และสิทธิ์.** admin สร้างบัญชีผู้ยืมพร้อม username และรหัสผ่าน; ผู้ใช้ล็อกอินและเห็นเมนูตามบทบาท; admin มีสิทธิ์ทุกอย่าง. ข้อมูลผู้ยืมที่เก็บ: ชื่อ-นามสกุล, เบอร์โทรศัพท์, เลขบัญชีและธนาคารที่รับเงิน ใช้สำหรับโอนเงินให้ผู้ยืม (ยืนยันแล้ว; ไม่เก็บอีเมลและเลขบัตรประชาชน). **ผู้ยืมต้องกดยอมรับเงื่อนไขการเก็บข้อมูลส่วนบุคคลตอนล็อกอินครั้งแรก** และระบบบันทึกวันเวลาที่ยอมรับ; **ผู้ยืมที่ยังไม่ยอมรับใช้งานระบบไม่ได้** และ **ไม่มีช่องทางขอแก้ไข/ลบข้อมูลในระบบ** (ยืนยันแล้ว; การจัดการคำขอแก้/ลบนอกระบบเป็นความรับผิดชอบของผู้ใช้)

**F2 — Master data (ค่าตั้งต้นการคำนวณ).** admin ตั้งค่าที่ระบบใช้คำนวณ — **ไม่มีค่าตั้งต้นจากผู้ใช้: อัตราดอกเบี้ยและอัตราค่าปรับ admin เป็นผู้ตั้งเองตอนเริ่มใช้งาน** (ยืนยันแล้ว; ระบบต้องไม่ฝังตัวเลขใดไว้)
- อัตราดอกเบี้ยแบบคงที่ (flat) หน่วย **% ต่อเดือน** เป็น **ค่าเดียวทั้งระบบ** (ยืนยันแล้ว; ค่าตัวเลขยังไม่ระบุ — ดู Open Questions)
- **ไม่มีผลิตภัณฑ์ระยะเวลาคงที่** วันครบกำหนดกำหนดเองต่อสัญญาอย่างเดียว (ยืนยันแล้ว)
- อัตราค่าปรับชำระล่าช้า % ต่อวัน เป็น **ค่าเดียวทั้งระบบ** ตั้งใน master data (ยืนยันแล้ว)
- ระบบไม่มีพารามิเตอร์เพดานดอกเบี้ย ผู้ใช้รับผิดชอบการตั้งอัตราเอง (ยืนยันแล้ว)

**F3 — คำขอยืมเงิน.** ผู้ยืมกรอก **จำนวนเงิน** และ **วันครบกำหนดที่เลือกเอง** เท่านั้น (ยืนยันว่าไม่ต้องกรอกหรือแนบอย่างอื่น) → สถานะคำขอ → ผู้อนุมัติอนุมัติ/ปฏิเสธ

**F4 — สัญญาและยอดที่ต้องชำระ.** เมื่ออนุมัติเกิดสัญญา; ดอกเบี้ยแบบคงที่คิดจากเงินต้นเต็มจำนวนตลอดสัญญา: **ดอกเบี้ย = เงินต้น × อัตรา % ต่อเดือน × (จำนวนวัน ÷ 30)** (**ปัดเศษขึ้นเป็นบาทเต็มเสมอ ไม่ปัดลง** — CR-2, ผู้ใช้ยืนยันแทนกฎเดิมที่ปัดขึ้น 2 ตำแหน่ง; ใช้กับค่าปรับรายวันด้วย) และ **ยอดที่ต้องชำระ = เงินต้น + ดอกเบี้ย** (ยืนยันแล้ว); วันครบกำหนดกำหนดเองต่อสัญญา (ไม่มีผลิตภัณฑ์ระยะคงที่ — ยืนยันแล้ว); **จำนวนวันในสูตรนับจากวันที่จ่ายเงินจริงถึงวันครบกำหนด** (ยืนยันแล้ว) จึงยืนยันยอดที่ต้องชำระได้เมื่อบันทึกการจ่ายเงินแล้ว

**F5 — การจ่ายเงินและการชำระคืน.** (ก) **การจ่ายเงินให้ผู้ยืม:** ใช้เลขบัญชีและธนาคารของผู้ยืมโอนเงินให้ และ **ระบบต้องบันทึกการจ่ายเงิน** ผูกกับสัญญา โดย **ผู้อนุมัติหรือ admin** เป็นผู้บันทึก; ข้อมูลที่บันทึก: **แนบสลิปการโอน (บังคับแนบทุกครั้ง), วันที่จ่าย, จำนวนที่จ่ายจริง, หมายเหตุ** (ยืนยันแล้ว; ไม่เก็บเลขอ้างอิงแยก — ต้องมีที่เก็บไฟล์สลิป). **จ่ายเท่าจำนวนที่ขอเสมอ ไม่มีกรณีหักค่าธรรมเนียมหรือจ่ายไม่เท่า** (ยืนยันแล้ว). **หลังอนุมัติ สัญญามีสถานะ "รอจ่ายเงิน" และยังไม่แสดงยอดที่ต้องชำระ** จนกว่าจะบันทึกการจ่ายเงิน จึงคำนวณและแสดงยอด (ยืนยันแล้ว). **สัญญา "รอจ่ายเงิน" ไม่หมดอายุ แต่ admin หรือผู้อนุมัติยกเลิกได้** (ยืนยันแล้ว). **บันทึกจ่ายเงินและรับชำระย้อนหลังวันได้ (ไม่ก่อนวันจ่ายเงินให้ผู้ยืม และไม่ใช่วันในอนาคต) แก้ไขรายการเดิมได้โดยตรง และ admin ลบรายการได้** (ยืนยันแล้วหลังรอบ design; ลบรายการจ่ายเงินให้ผู้ยืมได้เมื่อสัญญาไม่เหลือรายการรับชำระ แล้วสัญญากลับเป็น "รอจ่ายเงิน" — ปิดตามร่างตามคำสั่งผู้ใช้) **ห้ามจ่ายเกินยอดที่ติด — ระบบปฏิเสธ** (ยืนยันแล้ว) โดยระบบคำนวณยอด ดอกเบี้ย และค่าปรับของสัญญาใหม่ตามรายการที่แก้ (ข) **การชำระคืน:** รองรับ **จ่ายก้อนเดียว** และ **ชำระบางส่วนเพื่อลดต้น** (ยืนยันแล้ว); เจ้าหน้าที่/admin บันทึกการรับชำระ. **ชำระบางส่วน** ใช้คำในระบบว่า **"จ่ายเพื่อลดยอดรวมที่ติด"** (ผู้ใช้เลือกคำนี้เพราะเข้าใจง่าย) ทำได้ **ทั้งก่อนและหลังเลยกำหนด** (ยืนยันแล้ว): ลดยอดรวมที่ติด (เงินต้น + ดอกเบี้ย) แต่ **ดอกเบี้ยยังคิดตามเดิม ไม่ลดตามยอดที่ชำระ** (ตัวอย่างที่ผู้ใช้ให้: ต้นรวมดอก 1,000 จ่ายลด 200 เหลือ 800). **ผู้ยืมชำระคืนก่อนวันครบกำหนดได้ แต่ดอกเบี้ยไม่ลด** — จ่ายดอกเบี้ยเต็มตามวันครบกำหนดเดิม (ยืนยันแล้ว)

**F5-CR1 — ผู้ยืมแจ้งชำระและแนบสลิป (change request CR-1, 2026-10-30, ผู้ใช้ PM3 สั่งเพิ่ม).** ผู้ยืมส่งหลักฐานการโอนคืนเองได้ที่หน้าสัญญาของตน (จำนวนเงิน, วันที่โอน, รูปสลิป JPEG/PNG ไม่เกิน 5 MB, หมายเหตุ) **เป็นเพียง "คำแจ้ง" ไม่ลดยอดค้างทันที** — admin ตรวจสลิปแล้ว **กดยืนยัน** ระบบจึงบันทึกรับชำระจริงตามกฎเดิมทุกข้อ (ห้ามจ่ายเกิน, ตัดค่าปรับ → ดอกเบี้ย → เงินต้น, ไม่ก่อนวันจ่ายเงิน, ไม่ใช่อนาคต; admin แก้ยอด/วันที่ให้ตรงสลิปก่อนยืนยันได้) หรือ **ปฏิเสธพร้อมเหตุผลที่ผู้ยืมเห็น** (ผู้ใช้ยืนยัน 3 ข้อ: admin ตรวจแล้วยืนยัน; อนุญาตเพิ่มตารางใหม่ `PaymentSubmission`; แจ้ง admin ทันทีเมื่อผู้ยืมส่งสลิป) ข้อจำกัดที่ระบบกำหนดเพิ่ม: รอตรวจพร้อมกันได้ไม่เกิน 5 รายการต่อผู้ยืม; ผู้ยืมไม่เห็นสลิปที่ส่งกลับ (สลิปเปิดได้เฉพาะ admin)

**F6 — ค่าปรับชำระล่าช้า.** คิดเป็น **% ต่อวัน ของเงินคงเหลือที่ค้างชำระ** ตั้งแต่ **วันแรกที่เลยกำหนด** และ **ไม่มีเพดาน**; อัตราเป็นค่าเดียวทั้งระบบ (ยืนยันแล้ว). **ฐานคิดค่าปรับ = เงินคงเหลือ (เงินต้น + ดอกเบี้ยหลังหักยอดที่ชำระบางส่วนแล้ว) รวมค่าปรับที่สะสมแล้วด้วย (คิดซ้อน)** (ยืนยันแล้ว). ตัวอย่างผู้ใช้: ต้นรวมดอก 1,000 จ่ายลด 200 เหลือ 800 แล้วจ่ายไม่ทัน ให้เอา 800 ไปคิดค่าปรับ; **เมื่อบันทึกการจ่ายเพื่อลดยอดรวมที่ติด ฐานค่าปรับลดทันทีในวันที่บันทึก** (ยืนยันแล้ว). **ค่าปรับของวันที่บันทึกรับชำระครบทั้งก้อนยังคิดด้วย แล้วหยุดคิดตั้งแต่วันถัดไป** (ยืนยันแล้วหลังรอบ design; แทนถ้อยคำเดิม "หยุดสะสมในวันที่บันทึก"; ฐานที่ลดจากการจ่ายเพื่อลดยอดรวมที่ติดมีผลกับการคิดค่าปรับครั้งถัดไป เพราะค่าปรับของวันที่บันทึกคิดจากยอดต้นวันแล้ว ; หลักการที่ผู้ใช้ยืนยัน: **ค่าปรับคิดจากหนี้คงเหลือ ณ ปัจจุบัน** — รายละเอียดเวลาคิดอยู่ใน design DES-012) — ประเด็นด้านกฎหมายอยู่ใน Open Questions

**F7 — แจ้งเตือน.** ส่งถึง admin เท่านั้น ผ่านโทรศัพท์ ด้วย **LINE Official Account** และ **Web Push บนมือถือ (เว็บเป็น PWA)** เมื่อ: มีคำขอยืมเงินใหม่ (ส่งทันทีที่ผู้ยืมยื่นคำขอ — ยืนยันแล้ว); ถึงวันครบกำหนดชำระ ส่งเวลา **09:00** (เวลาไทย); เลยกำหนดชำระ ส่งเวลา **17:00** (เวลาไทย) **ตั้งแต่วันครบกำหนดถ้ายังไม่ชำระ และส่งซ้ำทุกวันจนกว่าจะชำระครบ** (ยืนยันแล้วหลังรอบ design; ผู้ใช้เลือกแจ้งในวันครบกำหนด ไม่ได้เลือกแจ้งล่วงหน้า). **การแจ้งแต่ละรอบเป็นข้อความสรุปเดียว รวมทุกสัญญาที่เข้าเงื่อนไขในข้อความเดียว** (ยืนยันแล้วหลังรอบ design)

**F8 — ประวัติผู้ยืม.** เก็บประวัติการยืมของผู้ยืมแต่ละคน (ผู้ใช้ขอโดยตรง); รายงานสรุปรายผู้ยืมต้องบอกได้ว่ายืมกี่ครั้งและจ่ายตรงเวลาแค่ไหน

**F9 — รายงาน.**
1. กำไรขาดทุน — แสดง **ทั้งฐานเงินสดและฐานค้างรับ ในรายงานเดียวกัน**; รายการมีเฉพาะ **รายได้ดอกเบี้ย + ค่าปรับ** ไม่มีหนี้สูญหรือค่าใช้จ่ายอื่น; ฐานค้างรับรับรู้ **ดอกเบี้ยเต็มจำนวนในวันครบกำหนด**; รายงานกรองช่วงเวลาได้ **รายเดือน, รายปี, และกำหนดช่วงวันเอง (จากวัน–ถึงวัน)** (ยืนยันแล้ว); **ค่าปรับรับรู้เป็นรายได้เมื่อบันทึกรับชำระจริงเท่านั้น**; เงินที่รับชำระ (รวมการจ่ายเพื่อลดยอดรวมที่ติด) **ตัดค่าปรับสะสมก่อน → ดอกเบี้ย → เงินต้น** (ยืนยันแล้ว; ตัวอย่างประกอบ: ยอดที่ติด 1,000 = เงินต้น 800 + ดอกเบี้ย 200 มีค่าปรับสะสม 50 ผู้ยืมจ่าย 300 → ตัดค่าปรับ 50, ดอกเบี้ย 200, เงินต้น 50 → รายได้ฐานเงินสดรอบนี้ 250)
2. ผู้ชำระช้าสุด — จัดอันดับตาม **จำนวนครั้งที่ชำระช้า** โดย **นับทีละสัญญาที่เลยกำหนด รวมสัญญาที่ยังไม่ได้ชำระ** (ยืนยันแล้ว)
3. ยอดเงินคงค้างรวม และจำนวนสัญญาที่เปิดอยู่
4. สรุปรายผู้ยืม (ยืมกี่ครั้ง จ่ายตรงเวลาแค่ไหน)

**F10 — นำเข้าข้อมูล (Import).** นำเข้าจากไฟล์ Excel/CSV ตามแม่แบบของระบบ ซึ่ง **มีคอลัมน์ดอกเบี้ยเพิ่ม** (ยืนยันแล้วหลังรอบ design เพื่อให้รายงานกำไรขาดทุนนับรายได้ดอกเบี้ยจากสัญญาเก่าได้) โดย **เฉพาะ admin เท่านั้นที่นำเข้าได้** (ยืนยันแล้ว); ผู้ใช้คัดลอกข้อมูลจากปฏิทิน iPhone ลงแม่แบบเอง (ยืนยันแล้ว). ข้อมูลเดิมมี 3 ช่อง: ชื่อผู้ยืม, จำนวนเงิน, วันครบกำหนดชำระ; คอลัมน์ **จำนวนเงินคือเงินต้นล้วน** ส่วนดอกเบี้ยอ่านจากคอลัมน์ดอกเบี้ยในไฟล์แล้ว **บวกเพิ่มจากเงินต้น** (ยืนยันแล้วหลังรอบ design — แทนข้อกำหนดเดิมที่ว่าจำนวนเงินคือยอดที่ต้องรับรวมแล้ว); ระบบไม่คำนวณดอกเบี้ยของสัญญานำเข้าจากอัตราเอง; ผู้ยืมคนเดียวยืมได้หลายครั้ง ชื่อผู้ยืมซ้ำในไฟล์จึงเป็นเรื่องปกติและผูกเข้าผู้ยืมคนเดิม และถ้ามีผู้ยืมคนละคนชื่อเดียวกันในระบบ admin เลือกผู้ยืมใน preview ก่อนยืนยันนำเข้า (ยืนยันแล้ว); สัญญาเก่าที่เลยกำหนดแล้วคิดค่าปรับ **ย้อนหลังตั้งแต่วันครบกำหนดเดิม** (ยืนยันแล้ว)

**F11 — ปฏิทินสำหรับ admin (change request CR-1, 2026-10-30).** หน้าปฏิทินรายเดือน: **สัญญาแต่ละฉบับถูกบันทึกลงในวันครบกำหนดของมัน** และ **รายการรับชำระลงในวันที่รับเงิน** กดที่วันเพื่อดูรายการ (สัญญาที่ครบกำหนด พร้อมยอดที่ยังค้างและวันที่เลยกำหนด, รายการรับชำระ, ยอดรวมของวันนั้น) — ใช้ข้อมูลเดิม ไม่มีตารางใหม่ และไม่มีการบันทึกโน้ตด้วยมือ

## Scope

**MVP (ทำในเฟสแรก):** F1–F10 ตามที่ระบุข้างต้น รวมการชำระบางส่วนเพื่อลดต้น (อยู่ใน F5)

**ภายหลัง / ยังไม่ทำตอนนี้ (ผู้ใช้ยืนยันว่า "ตอนนี้ยังไม่มี")**
- ต่ออายุสัญญา
- ปิดสัญญาก่อนกำหนดแบบลดดอกเบี้ย (การชำระก่อนกำหนดโดยดอกเบี้ยไม่ลดอยู่ใน F5)
- ยกเว้น/ปรับลดค่าปรับด้วยมือ
- ผ่อนชำระเป็นงวดตามตารางที่กำหนดไว้ล่วงหน้า (ชำระบางส่วนแบบไม่กำหนดงวดทำได้ตาม F5)

## Constraints & Assumptions

**ยืนยันแล้ว**
- ปริมาณงาน: ประมาณ 50–500 สัญญา (ผู้ยืมและสัญญาที่เปิดพร้อมกัน)
- ผู้ให้กู้องค์กรเดียว; ผู้ใช้ทุกบทบาทใช้ภาษาไทย
- ใช้งานบนโทรศัพท์เป็นหลักสำหรับ admin (รับ push)
- ดอกเบี้ยแบบคงที่ (flat) หน่วย % ต่อเดือน; จ่ายก้อนเดียวหรือชำระบางส่วนเพื่อลดต้นได้ (ดอกเบี้ยไม่ลด)
- วันครบกำหนดที่ตรงวันหยุด **ไม่เลื่อน** และค่าปรับนับวันตามปฏิทิน (ยืนยันแล้ว)
- กำหนดเริ่มใช้งาน: **ไม่มีวันกำหนดตายตัว — ระบบเสร็จวันไหนเริ่มใช้งานวันนั้น**
- ข้อมูลส่วนบุคคล (PDPA): **เก็บข้อมูลผู้ยืมถาวร** และ **เซิร์ฟเวอร์ตั้งอยู่ในประเทศไทย**

**สมมติฐาน (ยังไม่ยืนยัน)**
- (สมมติฐาน — ยังไม่ยืนยัน) สกุลเงินเป็นบาท (THB)
- (สมมติฐาน — ยังไม่ยืนยัน) เขตเวลา Asia/Bangkok สำหรับวันครบกำหนดและการคิดค่าปรับรายวัน
- (สมมติฐาน — ยังไม่ยืนยัน) ผู้ให้กู้มีบัญชี LINE Official Account อยู่แล้วหรือจะสร้างเอง

## Open Questions

ข้อที่ `system-analyst` ห้ามออกแบบทับโดยไม่ถามผู้ใช้ก่อน (รอบที่ 15 ปิดเรื่อง: ผู้อนุมัติเป็นคนเดียวกับ admin ไม่ต้องมีบัญชีแยก — ใน MVP ผู้ใช้ที่ล็อกอินจริงมีเพียง admin และผู้ยืม)

1. **กฎหมาย (ความเสี่ยงที่ผู้ใช้เลือกรับ):** ผู้ใช้เลือกไม่ให้ระบบตรวจ/จำกัดเพดานดอกเบี้ย และค่าปรับไม่มีเพดาน (รวมคิดค่าปรับซ้อน) — อ้างอิงเพดาน 15% ต่อปีใน References ยังไม่ได้รับการยืนยันจากทนาย; บันทึกไว้ให้ผู้ใช้ทราบ ไม่ขัดขวางการออกแบบ

## Declined / Not Pursuing

ตามที่ผู้ใช้ยืนยันในการสัมภาษณ์ — ยังไม่อยู่ในขอบเขตตอนนี้:
- แจ้งเตือนถึงผู้ยืม (ผู้ใช้ยืนยันว่าผู้ยืมไม่ได้รับแจ้งเตือน)
- ช่องทาง SMS (ไม่ได้เลือก)
- ข้อมูลเพิ่มในคำขอ: วัตถุประสงค์การยืม, สำเนาบัตรประชาชน, ผู้ค้ำประกัน, หลักประกัน (ผู้ใช้ตอบว่าไม่มี)
- ผู้ยืมสมัครบัญชีเอง (admin สร้างบัญชีให้เท่านั้น)
- ผ่อนชำระเป็นงวดตามตารางล่วงหน้า, ต่ออายุ, ปิดก่อนกำหนดแบบลดดอกเบี้ย, ยกเว้นค่าปรับด้วยมือ (ตอนนี้ยังไม่มี)
- รายงานเพิ่มเติม: ลูกหนี้ค้างชำระแยกตามอายุหนี้ (aging) และประมาณการรับชำระ 30 วัน (ไม่ได้เลือก)
- กฎแยกหน้าที่ maker/checker (admin ยื่นและอนุมัติเองได้)
- พารามิเตอร์/การตรวจเพดานดอกเบี้ยในระบบ (ผู้ใช้รับผิดชอบเอง)
- หนี้สูญและค่าใช้จ่ายอื่นในรายงานกำไรขาดทุน (มีเฉพาะรายได้ดอกเบี้ย + ค่าปรับ)
- เก็บอีเมลและเลขบัตรประชาชนของผู้ยืม (ไม่ได้เลือก)
- ผลิตภัณฑ์เงินกู้แบบระยะเวลาคงที่ (ผู้ใช้ยืนยันว่าไม่มี กำหนดวันเองต่อสัญญาอย่างเดียว)
- การลบข้อมูลอัตโนมัติ/กำหนดอายุการเก็บข้อมูล (ผู้ใช้เลือกเก็บถาวร)
- ช่องทางขอแก้ไข/ลบข้อมูลส่วนบุคคลของผู้ยืมในระบบ (ผู้ใช้ยืนยันว่าไม่ต้องมี)
- การหมดอายุ/ยกเลิกอัตโนมัติของสัญญา "รอจ่ายเงิน" (ไม่หมดอายุ ยกเลิกด้วยมือเท่านั้น)
- การแจ้งเตือนล่วงหน้าก่อนวันครบกำหนด (แจ้งเฉพาะวันครบกำหนด)
- การเลื่อนวันครบกำหนดเมื่อตรงวันหยุด
